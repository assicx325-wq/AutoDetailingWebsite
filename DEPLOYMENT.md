# Публикация BLACKLINE DETAILING

Сайт подготовлен для **Cloudflare Pages** как статический React/Vite-проект. Для него не нужны Worker Functions, база данных, API-ключи или платные сервисы.

## Сборка и настройки Pages

- Framework preset: `Vite`
- Root directory: корень репозитория
- Build command: `npm run build`
- Build output directory: `dist`
- Node.js: версия `22` из `.nvmrc`
- Environment variables: не требуются

`public/_headers` добавляет базовые заголовки безопасности и запрещает индексацию адресов `*.pages.dev`, пока демонстрационный сайт размещён на поддомене Pages. Дополнительное кеширование не задано: Cloudflare Pages применяет свои настройки кэширования статических файлов.

## Пошаговая публикация

### 1. Подготовьте демонстрационные данные

Откройте `src/data.js` и замените адрес, телефон, расписание, цены и фотографии, если публикуете проект для реального бизнеса. Для обычной публичной демонстрации оставьте `business.isDemo: true`: на сайте появится пометка «Демонстрационная версия», а форма останется выключенной для отправки.

Форма не отправит заявку в демонстрационном режиме даже при случайно заполненном `leadEndpoint`. Для реальных заявок потребуется backend: сначала подключите endpoint, настройте согласие и политику конфиденциальности, затем явно установите `business.isDemo: false`.

### 2. Проверьте проект локально

```bash
npm install
npm run build
npm run preview
```

Проверьте стартовую страницу, ссылки на секции, изображения и сообщение формы. Файлы Cloudflare `_headers` и `index.html` должны находиться в `dist/` после сборки.

### 3. Создайте пустой репозиторий GitHub

На GitHub нажмите **New repository**. Можно выбрать Public или Private. Не добавляйте при создании README, `.gitignore` или лицензию: эти файлы уже есть в проекте.

### 4. Отправьте проект из рабочей папки в GitHub

В терминале откройте папку `AutoDetailingWebsite` и выполните команды. Замените URL на адрес только что созданного репозитория:

```bash
git init -b main
git add .
git commit -m "Prepare BLACKLINE DETAILING for Pages"
git remote add origin https://github.com/ВАШ_АККАУНТ/ИМЯ_РЕПОЗИТОРИЯ.git
git push -u origin main
```

`.gitignore` исключает `node_modules/` и `dist/`; Cloudflare соберёт сайт из исходников.

### 5. Подключите GitHub к Cloudflare Pages

1. В Cloudflare Dashboard откройте **Workers & Pages → Create application → Pages → Connect to Git**.
2. Авторизуйте Cloudflare для нужного GitHub-аккаунта и выберите репозиторий.
3. Укажите параметры из раздела «Сборка и настройки Pages» выше.
4. Нажмите **Save and Deploy**. Это действие выполняется владельцем аккаунта; проект из этой рабочей сессии не публиковался.

После успешной сборки Cloudflare выдаст адрес вида `имя-проекта.pages.dev`. Последующие push в `main` запускают production-сборку; другие ветки дают preview deployments.

### 6. Проверьте опубликованный адрес

- Откройте главную страницу и обновите её напрямую.
- Откройте URL с неизвестным путём, например `/about`. Cloudflare Pages для проекта без корневого `404.html` применяет SPA fallback на `/`; этот сайт использует якорные ссылки для секций, поэтому отдельные маршруты ему не нужны.
- Убедитесь, что CSS/JS из `/assets/` загружаются и фотографии Unsplash доступны по HTTPS.
- Нажмите «Проверить данные»: форма должна сообщить, что заявка не отправлена и не сохранена.
- В Cloudflare build log проверьте, что вывод сборки находится в `dist/`.

## Что не подключено

Backend/CRM и сохранение заявок, реальные контактные данные, политика конфиденциальности и согласие, собственные домен и почта. Фотографии загружаются с Unsplash; для клиентского production-сайта замените их фотографиями с правами на использование.
